# 動画アーカイブを「読める記憶」にするための整理

2026-09-25時点の公開データと実装を確認したメモ。字幕の収集は継続しながら、読者が活動の概要、各動画の要点、問題と続報を順にたどれる形を目指す。

## 現状

- 公開動画554本。字幕取得115本、取得試行199本、取得不可など84本。Jev解析250本。これらは異なる母数である。
- 「自作MEMSマイクへの道・本編と前史」は54本中、字幕24本、Jev解析54本。既に字幕の時刻を根拠にしたSTV製作史14件がある。
- 現行の検索は字幕全文・タイトル・概要欄を対象とし、字幕から再生時刻へ移動できる。Jevは関連トピックと計画・実施・完成・問題の**記述候補**を抽出する。
- 公開ページの大半は原文、タグ、動画一覧である。字幕のない動画には内容の要約がなく、字幕があっても一目で何を試したか読み取りにくい。現行のJev処理は候補区間を最大12件選ぶ方式なので、記述が見つからないことを「話していない」と解釈できない。
- 週次Actionsは動画とプレイリストの公開情報を更新する。字幕取得・Jev解析・概要生成はローカルで別に進める。

## 読者に見せる三層

1. **全体像**: 技術製作、測定・修理、音楽・AI制作という入口から、シリーズの狙いと時期を短く読む。公式プレイリストの所属と推定トピックを区別する。
2. **動画の概要**: 1本ごとに「何を試したか／結果として何を報告したか／残した課題」を数文で示し、各文から字幕の時刻か概要欄へ戻れるようにする。未取得・未確認なら空欄の理由を表示する。
3. **テーマのつながり**: 個々の動画で述べた問題、試作、測定、再検討を同じ対象ごとに並べる。「後の動画が前の問題を解決した」は対象と根拠を照合できた場合だけ示す。

検索はこの三層を補助する機能とする。技術動画の「問題」と曲の歌詞・演出上の問題表現は混ぜない。

## いま着手できること

1. **既存の根拠を短い文章にする。** STV製作史から3つの要点を抜き出してページ冒頭に置き、字幕時刻へリンクする。詳細な製作史・タイトル由来の節目は必要な人が開く形にする。このリポジトリで先行実装する。
2. **取得範囲を入口ごとに表示する。** 全体の115/554だけでは各テーマの読み取り可能範囲が分からないため、シリーズ・プレイリストごとの字幕数と解析数を示す。音楽プレイリストの字幕数は、歌詞を技術的な製作記録と誤読しないように扱う。
3. **少数の動画で概要形式を試す。** 製作、測定、修理、AI制作から代表的な10〜20本を選ぶ。自動字幕の重複や誤認識を原文と照合し、概要の各文に時刻を付け、人が確認する。字幕がない動画はタイトル・概要欄に基づく仮の説明と明記する。
4. **保管形式を先に決める。** 原字幕は変更せず、整形済み表示文と概要を別ファイルにする。動画ID、字幕ハッシュ、生成方法と版、確認状態、根拠の時刻を保存し、字幕追加・修正時だけ更新する。

動画概要の最小レコード例（文面は模式例）:

```json
{
  "videoId": "...",
  "source": "transcript",
  "sourceHash": "...",
  "review": "draft",
  "summary": [
    { "text": "この動画で試したこと。", "evidence": [{ "start": 120, "end": 148 }] }
  ],
  "topics": ["STV2"],
  "issues": [
    { "subject": "対象となる回路・現象", "observation": "報告された問題", "evidence": [{ "start": 420, "end": 450 }] }
  ]
}
```

`review` は未確認・確認済みを区別する。時刻のない概要欄由来の文には `source: "description"` を使う。字幕自動生成の誤認識を直した場合も、原文と修正箇所の対応を保持する。

## 字幕が増えた後に進める分析

1. **動画単位の要約を増やす。** 字幕全文から構成をつかみ、冒頭・中盤・結論を偏りなく確認する。現行のJevの最大12区間の抽出結果だけで動画全体を要約しない。
2. **対象を同定する。** 例えば「STV2 AC版」「STV2 DC版」「LNA入力」を別の対象として記録し、表記揺れと同義語を管理する。
3. **出来事と関係を分けて保存する。** 「問題を報告」「対策を試す」「測定する」「後で再訪」「解決を本人が報告」の関係に、それぞれ前後の動画と根拠時刻を持たせる。単に同じトピックの動画が後にあるだけでは解決扱いにしない。
4. **テーマ別ページを作る。** 各テーマに短い現状説明、重要な転機、残る確認事項、関連動画を並べる。公開日と実際の作業日が異なる場合は区別する。未取得の期間は空白として見せる。
5. **横断的な問いに答える。** たとえば「低雑音化の課題が、マイク、プリアンプ、測定法にどう波及したか」を、同一対象と関係の根拠をたどりながら説明する。関係図はこの確認済みデータから描く。

「字幕完了」は全動画の取得成功を前提にしない。取得不能の動画を明示し、所有者の字幕ファイル取り込みなど代替手段を記録したうえで、テーマごとの網羅率と残る空白を示す。

## 公開前の確認

- 各概要文・関係に直接確認できる動画、字幕時刻、または概要欄を付ける。
- 試作の完成とプロジェクト全体の完了、当時の問題と現在の未解決を区別する。
- 代表例で「重要な出来事の拾い漏れ」と「別件同士の誤接続」を人手で点検する。モデルの数値を検証済みの正答率として表示しない。
- 新しい字幕で概要を再生成しても、確認済みの編集内容は無言で上書きしない。差分を確認してから公開する。
